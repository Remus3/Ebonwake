# 0005 - UI/UX audit of the dashboard and overlay (2026-10-05)

Status: research, read-only audit (task U1). No code changed.
Scope: `app/dashboard/*`, `app/overlay/*`, `app/shared/*`, `app/main.js`, the
server routes that feed them (`server/ew/app.py`), spec
`docs/design/0001-ebonwake-spec.md`, plans 001-018.

Method:
1. Code review of every renderer module, the shared CSS and pure logic, the
   Electron main process and the GET routes.
2. Live check: the server at 127.0.0.1:8940 answered `/api/health` ok. The
   dashboard and overlay were opened over the server's HTTP fallback
   (`/app/dashboard/index.html`, `/app/overlay/index.html`) in the built-in
   browser at the real content size 1264x761 (dashboard) and 340x220
   (overlay), dark scheme. 10 screenshots in `ops/runtime/ux/` (gitignored).
   No game window was touched.
3. Workflow walk-through of one play session (log in -> dailies -> grind ->
   market -> enhance -> log out), counting clicks and context switches.

## 1. Headline

The product is functionally rich (7 tabs, 8 plans of features) but reads as a
set of data-entry forms rather than a glanceable companion. Three things hurt
most today:

- The running server is 10 hours older than the app it serves and the UI still
  says `server ok` (live: `/api/version` commit 0044868, started 07:36 UTC;
  HEAD is 7e66457; `/api/spots` 404 and the Grind "Where next" card says
  "grind API not on this server yet"). Nothing tells the operator to restart.
- There is no "what should I do right now" surface: the spec goal (section 1)
  is answered across Today, Grind, Progress and Events, each one alt-tab and
  one tab click away, and the overlay omits the market ticker the spec and the
  acceptance criteria (section 8: "5 watched prices ... on the overlay") ask
  for.
- Cards stretch to fill the window (`grid-auto-rows: minmax(120px, 1fr)`),
  so every tab is 50-70 percent empty panel at 1264x761 while some lists
  (Hot list, Tuvala gear) scroll inside their card.

## 3. Workflow audit - one evening session

Assumes dashboard on a second monitor or behind the game, overlay on.

| Step | What the player does in EW today | Clicks / keys | Context switches (game <-> EW) |
|---|---|---|---|
| Log in | Nothing; game state dot flips by itself (plan 008). Overlay must be toggled with Ctrl+Alt+E if it was hidden. | 0-1 | 0 |
| Dailies | Alt-tab, Today tab (if not last tab), tick each daily as it is done in game (5 dailies -> 5 ticks, often done in batches). Events-tab coupons are a separate tab. | 1 + 5 ticks + 1 tab for coupons | 2-5 (one per batch) |
| Grind | Grind tab, choose spot, Start (3). Arm buffs: per buff, type minutes if not default, click arm (1-2 each, 3-4 buffs = 4-8). Optional XP sample in Progress tab (tab + 2 fields + Log = 4). End: Stop, type silver earned and trash (or: take screenshot in game, System tab, find shot, OCR, "use silver", back to Grind, Log = about 7). | 10-20 | 2-3 |
| Market | Market tab; to watch a new item: find its id outside EW (browser), paste id, thresholds, Save (about 6 + an external site). No alert reaches the overlay or a notification. | 6+ (plus browser) | 2 + browser |
| Enhance | Deadeye tab enhancement plan: tick step done (1). No link to market price of the item or materials; failstack / cost notes are free text. | 2 | 1-2 |
| Log out | Nothing recorded automatically; grind session must be stopped by hand or it keeps counting. No end-of-session summary. | 0-2 | 0-1 |

Total for a typical evening: about 30-45 clicks and 7-13 game <-> EW switches,
most of them to tick, arm or log - i.e. to feed data rather than to read it.

Missing glanceable information (not on the overlay or any single screen):
- Silver earned today / this week and silver/h of the current session.
- Market alert hits (a watched item crossed its threshold) - only visible in
  the Market tab list badge.
- Buff about to expire (e.g. 5 min left) and Hot Time starting - no toast or
  sound; overlay shows only the soonest buff.
- Dailies left (names, not just `2/5`) and the next weekly boss / weekly item.
- New coupon codes suggested by plan 014 - only in Events > Suggested.
- Grind session still running after the game exits (plan 008 knows the game
  closed; nothing prompts "stop session?").

## 5. Recommended order

1. F2 (S) - version-skew guard and System freshness: the live dashboard is
   lying about health today.
2. F10 + F11 (S) - density, focus-visible, overlay legibility, theme/scale.
3. F1 (M) - Home / Now tab, built on F10's grid.
4. F3 (M) - toasts and opt-in OS notifications.
5. F5 + F6 (M) - market ticker on the overlay with name search, and overlay
   placement off the minimap.
6. F4, F7, F9, F12 as follow-up plans.

All candidates stay inside the ToS floor: read-only data, operator input in
the dashboard, the overlay stays a click-through `globalShortcut`-toggled
window, nothing is sent to the game.
