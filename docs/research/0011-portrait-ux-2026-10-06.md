## 2. Attributing a portrait to a class

Finding: the client session log (plan 008 tail, already an allowed input)
writes, on character load, a service line naming the character number:

    "Log":"GameVariableManager <ko text>(<documents>/black desert/UserCache/<userNo>/500/<characterNo>/gameVariable.xml)"

On this host the FaceTexture stem appears 7 times across 3 logs, once per
character load (2026-10-04 x6, 2026-10-06 x1). No class name or class id is
logged ("deadeye" 0 hits). So the log gives `characterNo` + load time, and
`characterNo` = FaceTexture stem gives portrait -> character exactly. The
remaining hop is character -> class.

Options, in order of preference (automatic first):

| # | Source | Automatic? | Verdict |
|---|---|---|---|
| A1 | Single-character binding: exactly one characterNo ever seen in the log and the Progress character card has a class (`progress._default_character` is `Deadeye`; operator-confirmed one character) -> bind that characterNo to that class, `class_src: single`. | yes | ADOPT (covers today). |
| A2 | OCR class read: plan 066 `ocrinfer` gains kind `class` (the class name on the character window / My Info / character select, matched against a fixed class list) from a screenshot taken while characterNo X is loaded; at or over the 063 confidence gate it binds X, `class_src: ocr`. | yes | ADOPT (second character onward). |
| A3 | BDO-REST-API profile `characters[].class`: keyed by NAME, not number, and off by default (plan 061 robots). | n/a | Reject as a binding source (no number). |
| A4 | Typed bind (pick the class for an unknown character in the Deadeye tab gallery) as a plan 079 ledger entry. | no | Optional only, never required. |
| A5 | Filename / sidecar / folder per class. | - | Does not exist. |

A1 stops applying to a NEW characterNo as soon as a second one is seen; an
existing binding persists. Unknown-class portraits and screenshots are kept
in the index but shown in NO class slot (operator rule); the gallery lists
them only under "Unknown character" with the optional bind (A4).

Screenshots: a shot belongs to the characterNo of the most recent character
load line before its mtime within the same logged-in window (plan 062 play
sessions); a shot outside a logged-in window, or before EW recorded any load
line, is unknown.

## 3. ToS floor

Ruled by the `adjudicator` (2026-10-06): FaceTexture BMPs are an
operator-created Documents image, the same class as the ScreenShot watcher,
so a read-only copy is allowed while the game runs; the UserCache path is
parsed from the session-log string only and never opened.
Conditions (a breach is a floor defect): short-lived read handle (open,
read, close; on a sharing violation retry later); never write, rename,
delete, chmod or touch timestamps in FaceTexture; open nothing under
UserCache, Customization or the install dir; portrait data feeds no input
path; plan 082 adds a FaceTexture line to section 4 of research 0001 and a
test that no write-mode open targets that path.
Alternatives: game-closed-only reads (client-data-file reading); drop
portraits for a class icon / typed class.
Reverses if: PA or a GM names FaceTexture reads a violation, XIGNCODE3 is
seen flagging them, or a portrait save / display fails with a sharing
violation while EW runs (then: read only while the game is closed).

## 4. UI/UX audit: placement

Current shell (`index.html:11-17`, `ew.css:20-26`): one top bar, `EBONWAKE`
brand at the far left, then the tab list (`flex: 1`), server pill, restart
button; bar height about 38 px (6 px padding + 13 px text + tab padding).
Window 1280 x 800, min 960 x 600 (`main.js:48`); 0009 L2: the bar already
wraps badly at 960 px with `ui.scale` 1.3.

| Option | For | Against | Verdict |
|---|---|---|---|
| P1 Top-left identity chip in the top bar: portrait thumbnail 28 x 36 (the 624 x 804 aspect) + class name, replacing the brand text (brand stays as the window title and tray). | Visible on every tab; reminds which class is active as class tabs grow; costs one 28 px column; the brand word carries no information the title bar lacks. | Small image. | ADOPT. |
| P2 Header right, next to the server pill. | Right edge is status (server pill, 0009). | Identity reads as status; collides with restart button / wrap. | Reject. |
| P3 Home card. | Room for a large image. | Home is the 076 consolidated action screen (0009 section 3); a picture card pushes What now down; invisible on other tabs. | Reject. |
| P4 Deadeye tab only. | Natural home of class content. | Not visible while on other tabs - fails "reminds which class tab is open". | Use for the gallery, not the default slot. |
| P5 Overlay. | - | Overlay is in-game glanceable data; a portrait over the game adds no information and costs space. | Reject. |

Chosen: P1 chip + P4 gallery card.

Chip details:
- Content: `<img>` 28 x 36 CSS px (source thumbnail 56 x 72 for 2x DPI),
  `object-fit: cover`, 1 px `--fk-border` frame, radius 4 px; then the class
  name ("Deadeye") in the brand style. Below 600 px width (HTTP fallback,
  phone): thumbnail only, name in `title`.
- Which class: the class of the active class tab when a class tab is
  selected; otherwise the class of the most recently loaded character (log),
  else the Progress character class. Today always Deadeye.
- Action: the chip is a button that selects the class tab and scrolls to the
  Portraits card (optional; nothing needs it). `aria-label` "Deadeye
  portraits"; `title` "auto: newest portrait, <local date time>" or
  "pinned: <date> - newer portrait available" (plan 079 badge text).
- Empty state (no portrait bound to this class): the same 28 x 36 frame,
  empty, `--fk-border` dashed, no image, no silhouette, no art of any class;
  `role="img"` `aria-label="Deadeye: no portrait yet"`; `title` "Take your
  character portrait in game; EW picks it up automatically." No toast, no
  onboarding step (zero-touch: absence is not a task).
- Pinned marker: when a plan 079 entry pins an older image, a 6 px accent
  dot on the frame corner plus the title text (badge rule: visible, never
  silent).
- Themes: the frame uses `--fk-border` / `--fk-surface-2` tokens only; the
  image itself is not recoloured. Verified against tokens.css light and dark
  blocks (no hard-coded colour).
- Motion: none (no hover zoom); focus ring from the global `:focus-visible`.

Gallery card "Portraits" (Deadeye tab, first card, collapsed helper from 076
not used - it is the tab's identity):
- Current image 156 x 201 (source 312 x 402 thumb), source + age line
  ("auto - newest portrait, 6 Oct 20:48").
- Strip of thumbnails 48 x 62: portrait history for the class (every
  distinct FaceTexture version EW archived, newest first), then screenshots
  attributed to the class (newest 24). Arrow keys move, Enter picks;
  `aria-pressed` on the current one; each `alt` "Deadeye portrait, 6 Oct
  20:48" / "Deadeye screenshot, 6 Oct 21:02".
- Pick = plan 079 override `portrait.<class>`; "Use newest" retires it.
- Unknown-character images sit in a separate collapsed group with an
  optional "bind to class" select (A4); never shown in a class slot.

Privacy: images stay on the machine - originals read in place, copies and
thumbnails in gitignored `ops/runtime/portraits/`; served only by the EW
server on 127.0.0.1 (`ports.SERVER`, no port literal); never in a channel
note, log line, hand-off, commit or OCR upload; no network request carries
them. The dashboard CSP gains `img-src 'self' http://127.0.0.1:8940`
(today `default-src 'self'` would block them); overlay CSP unchanged.

Consistency with 0009: identity left, status right; no new Home card; no
zero-state card (0009 H4); human labels (M2); local-time display (M3).
