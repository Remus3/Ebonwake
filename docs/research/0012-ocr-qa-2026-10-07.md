## Root cause of the anomalies

1. No commits / no review: the shots carry no game UI (operator-side, not an
   EW fault). The silver QA needs shots with the UI shown and the inventory
   open, and the buff bar on screen.
2. today=27 for 25 files: BDO creates the PNG at 0 bytes and then writes it.
   The plan 008 watcher listed two shots mid-write (size 0); auto-OCR keys a
   shot by name|size|mtime and read the 0-byte listing at once, then the
   finished file again under its new key. One read was of a partial image
   (1 line), and each double read took a second daily-cap slot. A partial
   image could in principle yield a wrong silver read.

## Fix

`server/ew/ocrauto.py`: `scan()` neither queues nor marks seen a listing
with no positive size; `_process()` drops (uncounted, unseen) a queued shot
whose on-disk size no longer matches the listing. The finished file is
re-listed under a new key and read once. Tests:
`test_shot_listed_while_still_being_written_is_read_once_when_complete`,
`test_shot_still_growing_at_read_time_is_not_read_or_counted`
(synthetic files, no real screenshots).
